# House Climate

A Home Assistant custom integration that makes several HVAC systems act as one house thermostat. V1 targets Home Assistant 2026.10 and Python 3.14.2+, with temperatures in °C.

It computes a weighted house temperature from fresh member sensors and applies a separate PI offset to each system using that system's influence sensors. This lets a whole-house system warm cold rooms while a living-room system trims its own room. Devices share a heat/cool mode; automatic selection uses a deadband, minimum mode dwell, and outdoor temperature vetoes. Offsets have anti-windup, a configurable clamp and interval rate limit, and 0.5 °C rounding. Final targets respect each device's limits. Only changed commands are sent, and required hold presets are re-asserted during operation.

## Install

In **HACS → Custom repositories**, add `https://github.com/Fledgewing/house-climate` with type **Integration**. Download **House Climate**, restart Home Assistant, then go to **Settings → Devices & services → Add integration** and select **House Climate**.

Alternatively, manually copy `custom_components/house_climate` from this repository into `/config/custom_components/house_climate` on your Home Assistant host, restart Home Assistant, then add **House Climate** from **Settings → Devices & services → Add integration**.

## Configure

1. Select the room temperature sensors and climate entities to control. Any number of systems is supported. No entity IDs are preselected; temperature sensors are filtered by device class and HVAC systems by domain.
2. Give each sensor a positive weight and, optionally, a zone label. Zone labels are descriptive; weights determine the mean.
3. For each system, choose the member sensors it mainly influences. For example, a whole-house system can use all sensors while a room system uses only its room sensors. Set a required hold preset such as `manual` if your device needs one.
4. Select optional outdoor, fallback weather, solar power, and occupancy sources, then review the tunables. All configured sources must use °C for temperature; solar values are recorded in the source sensor's native unit (for example, kW).

Use the integration's **Configure** options to add or remove sensors and systems, change weights or influence lists, and edit tunables. Added sensors count in the house mean as soon as the updated configuration loads. Removing a system stops controlling it and leaves its last device settings in place.

Defaults: 5-minute control interval, 1 °C auto deadband, 60-minute minimum auto mode dwell, ±3 °C offset clamp, and 0.5 °C maximum offset change per interval. Cooling is vetoed below 10 °C outdoors; heating is vetoed above 24 °C. PI gains default to proportional 1.0 and integral 0.1 per interval. Explicit heat/cool requests take effect immediately, subject to the outdoor veto; minimum dwell applies to automatic heat/cool changes.

## Warmer / colder

Set the mode on `climate.house` to **heat**, **cool**, or **heat_cool** (automatic heat/cool selection). Its target starts at 21 °C and is restored after restart. The thermostat card's +/− buttons adjust the house target in 0.5 °C steps.

Press `button.house_warmer` or `button.house_colder` to change the same target by ±0.5 °C. A target or mode change runs control immediately; repeated presses do not bypass the offset rate limit. **Off** turns all available systems off.

`switch.house_climate_control` enables control by default. Turning it off observes and records without sending any commands, including off commands. Turning it back on immediately re-applies the house settings. The switch state survives restarts.

`sensor.house_temperature`, `sensor.house_temperature_spread`, and one `sensor.house_<system>_offset` per system explain the current readings and adjustments. `climate.house` exposes `last_decision`, the readings used, and the selected mode. Entity IDs shown here are the defaults generated by Home Assistant; renamed or conflicting IDs may differ.

Changes made directly on physical systems are noted in `last_decision` and re-asserted at the next interval. Sensors older than 30 minutes, unknown, unavailable, or nonnumeric are excluded. With no usable house sensors, targets fall back to the house setpoint with zero offsets; a system with no usable influence readings uses the same fallback. An unavailable system or failed service call does not block the others.

## State and recording

The integration persists the target, mode, integrators, offsets, and last mode-switch time in Home Assistant's `Store`, with `RestoreEntity` as a thermostat-state fallback. Each interval records every member sensor (including unavailable/stale readings), outdoor temperature, solar power, occupancy, and each system's observed mode, target, offset, and HVAC action. Observations are taken before commands. Records older than 30 days are pruned on each control run. Data lives in `.storage/house_climate.<entry_id>` under the HA config directory.

V1 uses configured influence lists. It records the data needed for future learning, but does not fit the phase 2 model.

uv sync --group dev
.venv/bin/pytest -q tests
uv run ruff check custom_components tests

The dev group pins `pytest-homeassistant-custom-component==0.13.375`, which targets HA 2026.10.4. The controller has no Home Assistant imports; its unit tests can also run with standalone pytest.
